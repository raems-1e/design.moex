Коллеги, подготовлена отдельная поставка MOEX Design для внутреннего контура.

По замечаниям ИБ:
— удалены встроенные C2PA/EXIF/text metadata в изображениях, включая пять указанных файлов; изображения не перекодировались. Отчёт с контрольными суммами приложен. AI-происхождение части изображений не скрывается и зафиксировано в документации;
— Google Fonts отключён на всех четырёх страницах, используется локальный Inter; лицензия сохранена;
— добавлены HTTP-заголовки CSP, X-Content-Type-Options, Referrer-Policy, X-Frame-Options; frame-ancestors 'none'. Inline JS вынесен в локальные файлы. Для существующей вёрстки/анимаций сохранён style-src 'self' 'unsafe-inline' — просьба подтвердить допустимость этого исключения для CSS;
— public/ и конфигурация Vercel исключены из внутреннего пакета.

Для адаптации добавлены README с запуском/конфигурацией/ответственностью, CLAUDE.md, rules/, VERSION, check.sh, .env.example, Dockerfile, compose.yaml, src/, app/ и tests/. Запуск: node app/server.mjs (или npm start), проверка: sh check.sh. Node.js 24; внешних npm-зависимостей нет. GET /health возвращает 200 OK. Настройки — переменные окружения, секретов не требуется.

Приложение не имеет пользовательского входа и не использует БД, API, очереди или LLM. Если требуется ограничить доступ сотрудниками, SSO должен обеспечиваться корпоративным ingress/порталом. Во время работы внешние зависимости не скачиваются. Ссылка на политику конфиденциальности moex.com остаётся обычной пользовательской ссылкой.

Локально пройдены синтаксические проверки и 3 набора тестов: маршруты/заголовки/изоляция файлов, локальные ресурсы, очистка метаданных. Docker build/run не проверен: Docker daemon в среде подготовки не запущен. Также требуется финальная браузерная проверка в контуре.

Просьба внести пакет через merge request, сохранить корпоративный CI, указать утверждённый Node 24 образ из внутреннего registry, повторить проверки ИБ/starter-pack и проверить ingress/healthcheck. Полное соответствие официальному стартовому пакету подтвердится повторным CI; сейчас структура собрана по перечню портала. После принятия MR можно закрывать техдолг по README и отмечать подтверждённые пункты адаптации.

Отдельно: фотографии/имена сотрудников требуют подтверждения права размещения владельцем контента. Материалы для скачивания пока не наполнены — это сохраняется как отдельная контентная задача.
